# 本地双币账本 · 使用说明

一个在自己电脑上运行的中文记账网站，支持人民币（CNY）和新加坡元（SGD）、收支记录、双钱包、换汇、照片、分类统计、备份与恢复。

**每个人 Fork 或下载的是同一套程序，运行后使用自己的独立账本。仓库中没有作者的账目、余额、照片或备份。**

## 1. 准备环境

已在 **Windows + Python 3.14** 上验证。下面优先介绍 Windows 操作；其他系统的命令行启动需要自行验证，Windows 的 `.bat` 和桌面快捷方式脚本不适用于它们。

你需要：

- 一台可以安装 Python、保存本地文件的 Windows 电脑。
- Python **3.14** 运行时，以及 Edge、Chrome 等现代浏览器。
- GitHub 账号：用于 Fork；只下载源码使用不要求注册账号。
- Git：仅在选择 `git clone` 下载或 Git 更新时需要，下载 ZIP 的用户不需要安装。

程序只使用 Python 标准库，**无需 `pip install`、Node.js、npm、Docker、数据库服务器或 API Key**。Inter 字体已随源码提供，无需另外安装。

### 安装并检查 Python

从 [Python 官网](https://www.python.org/downloads/)安装 Python 3.14。使用传统安装器时，如有 **Add Python to PATH** 选项，请勾选；如果使用新版 Python Install Manager，还需要安装实际的 Python 运行时。新版管理器可执行 `py install 3.14`，这条安装命令不适用于旧版 Python Launcher。参考 [Python 官方 Windows 说明](https://docs.python.org/3.14/using/windows.html)。

安装后重新打开 PowerShell，运行：

```powershell
python --version
python -c "import sqlite3, http.server; print('Python ready')"
```

建议确认第一条显示 `Python 3.14.x`，第二条显示 `Python ready`。如果 `python` 不可用但 `py -3.14 --version` 可用，可以暂时用后文的 `py -3.14` 命令启动；双击 BAT 和创建桌面快捷方式仍需要 `python` 命令配置正确。

## 2. Fork 并下载到电脑

### 第一步：在 GitHub 创建自己的副本

1. 登录 GitHub，打开 [ZHX-ctrl/local-ledger](https://github.com/ZHX-ctrl/local-ledger)。
2. 点击页面右上角 **Fork**。
3. **Owner** 选择自己的账号；仓库名可以保留 `local-ledger`。
4. 只复制默认分支即可，点击 **Create fork**。
5. 创建后，检查页面地址已变成你自己账号下的仓库。

Fork 是 GitHub 上的源码副本；这一步还没有把程序下载到电脑。具体按钮可参考 [GitHub 官方 Fork 指南](https://docs.github.com/en/pull-requests/how-tos/work-with-forks/fork-a-repo)。

### 第二步：下载源码，两种方式任选其一

**方式 A：下载 ZIP，适合不熟悉 Git 的用户**

1. 在你 Fork 后的仓库页面，点击 **Code → Download ZIP**。
2. 将 ZIP **完整解压**到自己的固定文件夹，例如 `D:\Apps\local-ledger`。这只是示例路径，也可以选择自己的本地文档目录。
3. 打开解压后的实际项目文件夹，确认能看到 `run_ledger.py`、`启动记账.bat` 和 `ledger_app`。
4. 如果外面还有一层 `local-ledger-main`，继续进入到包含这些文件的那一层。

不要直接在压缩包预览窗口中启动。请选择自己有读写权限的普通本地文件夹，不要放在系统目录或只读目录；如果使用会自动同步的文件夹，云盘软件可能另行上传账本数据。

**方式 B：使用 Git 克隆，适合需要持续更新的用户**

在自己选定的存放位置打开终端，执行下面两行。先把 `YOUR-USERNAME` 替换为自己的 GitHub 用户名；如果改过仓库名，也相应替换：

```powershell
git clone https://github.com/YOUR-USERNAME/local-ledger.git
cd local-ledger
```

每个人在自己的电脑上下载一份源码即可。不要为了分享程序而复制其他人的 `private/` 文件夹。

## 3. 第一次启动

### 方法 A：双击启动

1. 打开包含 `run_ledger.py` 的项目文件夹。
2. 双击 **启动记账.bat**。
3. 等待窗口显示 `本地账本已启动：http://127.0.0.1:8765`。
4. 浏览器会自动打开记账页面；如果没有自动打开，在地址栏输入：

   **http://127.0.0.1:8765/**

使用期间保持这个命令窗口开启。窗口显示备份检查失败时，可以查看账本，但要先按错误提示解决问题才能保存，详见[常见问题](#13-常见问题)。

### 方法 B：在终端启动

在项目文件夹的资源管理器地址栏输入 `powershell` 并回车，然后执行：

```powershell
python -X utf8 run_ledger.py
```

如果你只有可用的 Python Launcher：

```powershell
py -3.14 -X utf8 run_ledger.py
```

两种命令任选一种，不要同时启动。不要直接双击 `ledger_app/static/index.html`，界面必须通过本机服务访问才能保存记录。

### 第一次打开应该看到什么

- 收支列表为空，钱包显示 **待初始化**。
- 有一些默认类别，可以在“类别管理”中调整。
- 项目内自动生成 `private/` 文件夹，保存你自己的账本。
- 不会预填任何人的余额或消费，也不需要登录作者的账号。

### 以后如何打开和关闭

- **命令窗口启动**：以后双击同一个“启动记账.bat”。先保存完记录，再关闭启动窗口，或在窗口中按 `Ctrl+C`，即可停止服务。
- **只关闭浏览器标签页**：不会停止命令窗口中的服务，可以重新打开本机网址。
- **重启电脑后**：重新启动一次，原数据仍从同一个 `private/` 读取。
- **服务已经运行**：无需重复启动，直接进入网址即可；支持自动检查和复用的桌面入口见下一节。

`127.0.0.1` 代表当前这台电脑。同一个网址在朋友的电脑上访问的是朋友自己的本机服务，不会连接到你的账本。

## 4. 创建桌面快捷方式

仅适用于从 GitHub 下载的完整源码。先确认上一节能正常启动，保存完记录并关闭命令窗口，再配置快捷方式。

在项目文件夹打开 PowerShell，执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\创建桌面快捷方式.ps1"
```

这条命令只为本次脚本进程设置执行策略，不修改系统的永久执行策略。脚本会在本机生成图标和桌面上的 **记账** 快捷方式；若电脑的组织策略禁止运行脚本，继续使用 BAT 入口即可。

以后双击桌面“记账”：

- 未启动时，会在后台启动服务，等待页面就绪，再打开浏览器。
- 同一本账已运行时，会直接打开页面。
- 关闭浏览器不会停止后台服务；重启电脑后再次双击即可。
- 不会添加开机自启动。

请保留项目所在位置。移动项目后，重新运行创建快捷方式脚本，让快捷方式指向新位置。它依赖 `python.exe` 与同一安装目录中的 `pythonw.exe`；找不到时先修复 Python 安装或使用命令窗口入口。

后台入口没有单独的“退出服务”按钮。更新或迁移前，需要结束此项目的服务：熟悉任务管理器的用户可核对命令行中的项目路径与 `run_ledger.py` 后，只结束对应进程；不熟悉时，可先重启电脑，重启后暂不启动账本，完成文件操作后再打开。不要批量结束其他 Python 程序。

## 5. 初始化自己的钱包

### 先确定统计范围

本系统按币种各维护一个合计钱包：**人民币钱包**和**新加坡元钱包**。它不是每张银行卡各有一个余额的银行账户管理系统。

先确定你想纳入的现金、银行卡等范围，然后使用同一范围填写真实余额、记录收支。同币种自己账户之间转账不会改变这份合计余额。

### 填写操作

1. 左侧进入 **钱包与余额**。
2. 在 **录入余额快照** 中选择“钱包币种”。
3. 填写你自己的“实际余额”。
4. 选择“截至日期（当日 23:59）”。它表示该日结束时的真实余额。
5. 点击 **保存余额快照**；需要另一币种时，再单独填写一次。

默认日期只是输入提示，请核对后再保存。暂时不知道余额，可以先记录收支，钱包会保持“待初始化”；确认后再补录余额。不要为了消除提示而填写猜测值。

### 截止日期决定哪些账会影响钱包

```text
当前钱包余额
= 余额快照中的实际余额
+ 截止日之后的同币种收入
- 截止日之后的同币种支出
+ 截止日之后实际换汇转入
- 截止日之后实际换汇转出
```

- 发生日期 **晚于** 截止日：保存成功就会更新相应钱包，收入增加、支出扣除。
- 发生日期 **早于或等于** 截止日：视为已包含在快照余额中，只更新历史记录和月份统计，不再次扣款。
- 判断依据是账目的**发生日期**，不是你在哪一天录入。
- 编辑或删除记录后，余额会按仍然有效的记录重新计算，不需要等周末或月底。
- 有多次快照时，以**截止日期最新**的一份为基准；同一天有多份时，采用最后保存的那份。补录更早日期的快照不会替换较新的基准。

**以下仅为虚构演示，请不要照抄为自己的余额：**

| 操作 | 该演示的新币钱包 |
| --- | --- |
| 填写 2025-01-31 日终余额 SGD 1,000.00 | SGD 1,000.00 |
| 记一笔 2025-02-01 的支出 SGD 12.50 | SGD 987.50 |
| 补记 2025-01-15 的支出 SGD 20.00 | 仍为 SGD 987.50；只更新一月份记录 |
| 记一笔 2025-02-02 的收入 SGD 50.00 | SGD 1,037.50 |

**如果希望今天发生的每笔消费都扣款，应使用昨天日终或更早日期的真实余额做基准。** 如果把截至日期设为今天，今天的记录也会被视为已经包含在基准中。只有今天此刻的余额、却不知道昨天日终余额时，可以先记收支，待核对完毕或当天结束后再填写对应的日终余额，不能随意把“现在余额”写成“昨天余额”。

## 6. 添加和管理收支

### 记一笔账

1. 点击右上角 **＋ 新建记录**，或进入 **收支记录**。
2. 选择“类型”：支出或收入。
3. 选择实际“发生日期”，补记旧账就填写旧账日期。
4. 选择“币种”：新建记录默认是 **SGD 新加坡元**，人民币账目需要改为 CNY。
5. 填写正数金额、名称和类别；收入也填正数，通过“类型”区分收支。
6. 按需填写备注、添加照片，点击 **保存记录**。
7. 等待保存成功提示和回执。失败提示不代表已记入，应解决问题后再操作。

金额最多两位小数，输入框不要填写币种符号或千位逗号。日期不能晚于本机 UTC+8 的当天。金额显示时的千位分隔符只是排版，不改变实际值。

系统发现疑似重复时会要求确认。先检查是不是同一笔已保存的账，只有确实为另一笔相同消费时才确认继续。

### 添加多张照片

- 每笔最多 **20 张**，支持 **JPEG、PNG、WebP**，每张不超过 **8 MiB**。
- 选文件时可以按 `Ctrl` / `Shift` 多选，也可以分次追加。
- 保存前可逐张预览、移除；编辑记录时，没有移除的原照片会保留。
- 记录列表中，照片缩略图横向放在名称右侧，较多时可以横向滚动，点击可看原图。
- 界面中的“上传照片”是从浏览器传到你自己电脑上的本地服务，不是上传 GitHub 或图片识别网站。
- 删除关联或删除账目，不会自动清除照片原文件及历史备份中的副本。

HEIC、PDF、GIF 或仅改了扩展名的文件可能不支持。需要时先在本机图片工具中另存为真正的 JPEG/PNG；不要仅把文件名改成 `.jpg`。

### 编辑和删除

在记录右侧选择 **编辑** 或 **删除**，删除会弹出确认。编辑金额、币种、日期或收入/支出类型后，系统会重新计算受影响的钱包；仍然遵守上一节的截止日规则。

### 管理类别

在 **类别管理** 中新增或编辑类别：

- **停用**：不再用于新记录，历史账目仍保留原分类，旧账可保留该分类。
- **删除**：从管理列表和新建选项中移除，历史账目与原分类名称仍保留，不删除金额或改变钱包。
- 筛选历史记录时，使用过的已删除分类会有相应标记。
- 重新创建同名类别会产生一个新类别，不会自动改写旧记录的分类。

## 7. 查找记录与查看统计

### 总览

在“总览”右上角选择 **统计月份**，查看该月收入、支出和支出类别。人民币、新币分别合计，不把新币合计折算后叠加到人民币中。

钱包卡片显示的是按余额基准和全部有效流水算出的**当前余额**，不是所选月份的月末余额。切换统计月份不会重置钱包或删除记录。

### 查找记录

进入 **收支记录 → 查找记录**，可以按日期、类别、币种、名称或备注、原币金额筛选。

- 不填写起始和结束日期：默认查“总览”所选月份。
- 填写任一日期：使用填写的日期范围；只填起始日期表示该日及之后，只填结束日期表示该日及之前，另一端不设限制。
- 金额为精确匹配。例如金额填 `6`、币种选 SGD，会找到原币为 **SGD 6.00** 的记录；选 CNY 则查 **CNY 6.00**；全部币种会同时匹配两者。这里的数字仅为筛选示例。
- 金额输入会自动应用筛选，其他条件也可以组合后点击 **应用筛选**。
- 金额匹配原币金额，不匹配人民币参考折算值；收入与支出都可能出现在结果中。
- 点击 **清除筛选**，回到所选月份的默认记录范围。

列表按日期倒序分组，点击日期或星期右侧箭头可收起、展开当天明细。每天的收入和支出小计只汇总当前筛选结果；首页月度汇总仍按所选月份统计。

## 8. 换汇与内部转账

| 实际发生的事情 | 使用什么功能 | 钱包与统计如何变化 |
| --- | --- | --- |
| 买东西、支付费用 | 支出 | 对应币种钱包扣款，计入支出 |
| 收到收入、退款等 | 收入 | 对应币种钱包增加，计入收入 |
| 人民币实际换成新币，或反向兑换 | 换汇记录 | 按实际转出、到账金额改变两个钱包，不计为收入或支出 |
| 自己同币种的银行账户、现金之间转移 | 收支记录页面下方的内部转账 | 只记录资金移动，不改变该币种合计钱包，不计收支 |

表中的钱包变化均以交易日期晚于对应钱包基准日为前提。

**实际换汇**：先初始化两个钱包，再进入“换汇记录”，填写日期、转出币种和实际金额、到账币种和实际到账金额。这里采用你真实成交的金额，不使用参考汇率代替实际收付。

**内部转账**：填写日期、币种、金额、转出账户名称和转入账户名称。它不会维护每个银行账户的独立余额。给其他人的付款不属于自己的内部转账，应按实际用途记录。

## 9. 汇率与离线使用

### 新币账目怎样折算

- 每笔新币记录保留原始 SGD 金额，同时保存或等待计算人民币参考金额。
- 按**发生日期**查询汇率。以后补记以前的消费，也不会套用录入当天的汇率。
- 人民币账目保持人民币，不反向折算新币。
- 新币的人民币参考金额不会再扣一次人民币钱包；月度原币收支也不会重复加总它。

唯一来源为 [Frankfurter](https://frankfurter.dev/) 的 ECB 数据，使用固定接口 `https://api.frankfurter.dev/v2/providers/ecb/rate/sgd/cny`。ECB 参考汇率按工作日发布，并非实时行情；银行卡、支付平台或换汇商的成交价可能不同。[ECB 来源说明](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html)

周末和代码支持的 TARGET 休市日沿用之前最近工作日的报价；普通工作日尚未取得对应报价、网络失败或响应不符合校验时，原币账目仍可保存，人民币折算显示 **待更新**。已经确定的历史汇率不会随今天的报价变化。

首页显示的是**本地已经取得的最近一条参考汇率及其实际报价日期**。日期不是今天，可能是尚未公布、休市或本次联网未成功，不应把它当成实时汇率。正常联网启动会尝试刷新，也可在 **换汇记录** 页点击 **更新待汇率**。一次最多处理 10 个日期（包含今天），积压较多时可能需要多次更新。

### 完全离线启动

保存完记录、停止已运行的服务后，在项目文件夹执行：

```powershell
python -X utf8 run_ledger.py --offline
```

离线模式下不主动向汇率服务发请求，已有缓存仍可使用；没有相应汇率的记录保持待更新。下次需要补齐时，停止服务，再不带 `--offline` 正常启动。仅打开网站或记账不需要 GitHub 在线。

## 10. 备份恢复与换电脑

### 数据保存在哪里

默认保存在项目根目录的 `private/` 中。关闭页面、停止服务或重启电脑都不会删除它。换一个没有 `private/` 的新文件夹启动，会得到另一份空账本。

### 创建完整备份

1. 进入 **备份与导出**。
2. 点击 **立即创建备份**。
3. 确认成功，并在“已有备份”中看到新条目。
4. 文件位于 `private/backups/`。如果需要防范硬盘损坏，应另行把自己的备份复制到自己保管的安全磁盘；程序不会替你上传云盘。

自动备份在启动时检查，并在跨日后的首次业务写入前检查；自动备份保留最近 **30 份**，手动备份单独保留。它不是每一笔记录各生成一份备份，也不能替代电脑之外的备份副本。

备份包括数据库和照片，也可能包含已经解除关联的照片。备份文件同样属于个人隐私资料。当前完整备份有规模限制：ZIP 文件及解压总量各不超过 512 MiB、数据库不超过 256 MiB、归档成员不超过 10,000 个；如果照片长期累积并触发限制，先保留已有数据与备份，再处理具体报错，不要直接清空照片目录。

### 恢复已有备份

1. 在 **备份与导出 → 已有备份** 中核对要恢复的文件。
2. 点击 **恢复** 并确认。
3. 系统会校验所选备份，并在切换数据前保留一份恢复前备份。
4. 成功后重新读取页面，核对日期、记录、钱包和照片。

恢复会把当前账本切换到那个备份时点，之后新增的记录不再出现在恢复后的账本中。它不是“合并导入”。界面列出本机 `private/backups/` 中的 ZIP 文件，无法识别的可能显示为“未知”；没有任意文件上传恢复按钮。只有应用生成且通过当前版本校验的完整备份才能恢复，普通 ZIP 或 CSV 不能恢复。

### 导出 CSV

“导出 CSV”沿用当前查找条件，包含筛选后的**收支记录和内部转账**，不包含换汇记录、余额快照或照片。它适合表格分析，**不是完整备份**；当前也没有把任意银行 CSV、Excel 或 PDF 自动导入账本的功能。

### 把自己的账本搬到另一台电脑

1. 在旧电脑上创建一次完整备份，确认没有尚未保存的操作，然后停止服务。
2. 在新电脑下载相同版本的源码并安装 Python，先不要启动。
3. 通过自己控制的本地介质，将旧项目的**整个 `private/` 文件夹**复制到新项目根目录下，与 `run_ledger.py` 同级；数据库应位于 `新项目/private/ledger.sqlite3`。只迁移自己的数据，不通过公开仓库、Issue 或 PR 传递。
4. 在新电脑启动，核对记录、余额和照片；确认成功前保留旧电脑和备份原件。
5. 原桌面快捷方式不会自动跟随迁移，需要在新位置重新创建。

如果新电脑已有另一份账本，不要直接覆盖或合并两个 `private/`。选择一个全新的项目文件夹进行迁移。迁移后两台电脑仍是独立副本，不会自动同步后续修改。

## 11. 更新自己的版本

**更新的是程序源码，账本仍保存在本机。** 更新前先创建完整备份并停止服务。不要删除 `private/`，也不要在正在写账时替换程序文件。

### Git 克隆的用户

1. 在 GitHub 打开自己的 Fork，点击 **Sync fork → Update branch**。[GitHub 官方同步说明](https://docs.github.com/en/pull-requests/how-tos/work-with-forks/syncing-a-fork)
2. 回到本地项目目录，执行：

```powershell
git status --short
git branch --show-current
```

确认第一条没有输出待处理的源码修改，第二条显示当前分支是 `main`，再执行：

```powershell
git pull --ff-only origin main
```

若你改过程序、发生冲突或不能快进更新，先保留修改并处理差异，不要用强制覆盖或删除文件的方式跳过问题。

3. 重新启动服务并刷新浏览器。桌面后台服务也需要先停止，单纯刷新浏览器不会重新加载已经运行的 Python 后端。

### 下载 ZIP 的用户

先在 GitHub 同步自己的 Fork，再下载新 ZIP，解压到一个**新文件夹**。按上一节的方法，在服务停止后把自己的完整 `private/` 复制过去，再启动、核对；确认无误前保留原文件夹。新位置需要重新创建桌面快捷方式。

## 12. 分享独立空账本

最简单的方式是把本仓库链接发给朋友，让对方按本文 Fork 或下载。对方首次启动会创建自己的数据文件夹。

也可以在完整源码目录执行：

```powershell
python -X utf8 制作分享版.py
```

程序按固定源码清单生成 `dist/双币账本-独立版-日期.zip`。打包不会遍历整个项目，不包含 `private/`、照片、账本、备份、CSV、Git 历史或开发临时文件。

分享包接收者仍需安装 Python，完整解压后双击“启动记账.bat”，参考包内“分享版使用说明.txt”。这个精简分享包不含桌面快捷方式脚本和测试；需要这些文件时下载 GitHub 完整源码。

不要把自己正在使用的整个项目文件夹直接压缩发给别人，因为其中已经有你的 `private/`。

## 13. 常见问题

| 现象 | 检查和处理 |
| --- | --- |
| 提示找不到 `python`，或运行后打开商店 | 重新打开终端检查 `python --version`；确认已安装实际 Python 运行时并配置 PATH/应用执行别名。若 `py -3.14` 可用，先用它命令行启动；再按 Python 官方 Windows 说明修复入口。 |
| 双击窗口一闪而过 | 在包含 `run_ledger.py` 的文件夹打开 PowerShell，执行 `python -X utf8 run_ledger.py`，读取完整错误。不要在压缩包内运行。 |
| 浏览器没有自动打开 | 确认启动窗口已显示服务地址，再手动访问该地址。 |
| 页面显示无法访问或连接失败 | 本机服务需要正在运行；关闭命令窗口或重启电脑后要重新启动。检查实际端口是否仍是 8765。 |
| 提示“这个账本已经在运行” | 使用同一项目已打开的页面，或双击该项目的桌面快捷方式。不要删除锁文件来强行启动第二个服务。 |
| 提示端口被占用 | 先核对是不是自己的账本已启动；若是其他程序或另一份账本，可使用 `python -X utf8 run_ledger.py --port 8766`，然后打开 `http://127.0.0.1:8766/`。不要随意关闭不认识的进程。 |
| “写入前备份失败，账本未改变” | 查看启动窗口或 `private/work/desktop-startup-*.log` 的具体原因；确认项目及 `private/` 可读写、磁盘空间充足、照片目录可读，检查安全软件是否阻止本程序访问。修复具体问题后重试，不要删账本或关闭备份保护。 |
| 保存新币账后人民币金额“待更新” | 原币记录可以已经保存成功。检查发生日期、实际报价日和网络，在“换汇记录”点“更新待汇率”；不要因此重复添加同一笔账。 |
| 钱包余额没扣，但记录已保存 | 检查该币种是否初始化，以及发生日期是否早于或等于余额截止日；该类历史记录不会再扣款。 |
| 找不到以前的记录 | 检查总览统计月份、查找日期范围及其他筛选条件；钱包余额不随月份选择变化。 |
| 显示照片不支持 | 核对实际格式、文件是否损坏及是否超过 8 MiB；在本机另存为 JPEG/PNG 后重试，改扩展名不等于格式转换。 |
| 换目录或重新下载后变成空账本 | 新位置没有原来的 `private/`，不是原账本被清空。停止服务后找到原目录，按迁移步骤处理。 |
| 页面写着“已同步” | 表示浏览器已读到本机服务的数据，不代表上传 GitHub、云盘或同步到手机。 |
| 朋友 Fork 后仍打不开我的记账页面 | 每个人需要在自己电脑上启动。GitHub 仓库页面与本地记账网页是两个入口，Fork 不会提供共享在线账本。 |

如果需要报告故障，请只提供必要的错误文字、系统/Python 版本以及虚构复现步骤。先检查截图和日志，去掉余额、姓名、路径、账号等个人信息；不要把 `private/`、数据库、照片或完整备份附到公开 Issue。

## 14. 隐私与文件说明

```text
local-ledger/
├─ README.md                 使用说明
├─ 启动记账.bat              命令窗口启动入口
├─ 创建桌面快捷方式.ps1       Windows 桌面入口生成脚本
├─ run_ledger.py             本机服务启动器
├─ desktop_launcher.py       桌面后台启动器
├─ ledger_app/               程序与网页源码、本地字体
├─ tests/                    虚构数据测试
├─ 制作分享版.py             只打包指定源码
├─ private/                  运行后生成：你的个人账本，禁止上传
│  ├─ ledger.sqlite3         数据库
│  ├─ photos/                照片
│  ├─ backups/               完整备份
│  ├─ exports/               CSV 导出
│  └─ work/                  启动日志和私有工作文件
└─ dist/                     分享包输出，默认不纳入 Git
```

`private/` 中还会有运行状态、锁及会话文件，应整体保管。它不做应用层文件加密；同一台电脑上能读取这些文件的其他程序或账号，也可能访问数据。需要隔离时使用自己的操作系统账户和文件权限。

- 本机服务仅监听 `127.0.0.1`，不对局域网或公网开放；当前没有多人登录、权限分账或手机同步。不要把服务端口通过公网隧道暴露出去。
- 运行时没有广告、访问统计 SDK、远程字体或 CDN。程序主动外网请求仅用于参考汇率，发送币种和日期，不发送账目名称、金额、备注、照片或钱包余额；联网服务仍能接收连接所需的常规网络信息。
- `.gitignore` 采用“默认忽略，仅允许指定源码”的规则，排除 `private/`、照片、备份、导出、临时文件和本机配置。
- 忽略规则不能阻止人为强制提交，也不能保护被复制进 README、源码、测试或截图中的隐私。**不要强制添加私有文件，不要把真实账目写进已跟踪的源码或公开文档。**
- 自己的公开 Fork 也应只保存程序。GitHub 更新、Fork、Pull Request 都不是账本备份或数据同步功能。
- 如果想在同一电脑使用不同账本，应使用各自独立的项目目录；同时启动时需要不同端口。程序本身不提供账号登录隔离。

## 15. 开发与本机接口

日常使用不需要本节。接口细节见 [CONTRACT.md](CONTRACT.md)，项目数据操作约定见 [AGENTS.md](AGENTS.md)。

### 启动参数

| 参数 | 用途 |
| --- | --- |
| `--no-browser` | 启动服务，不自动打开浏览器 |
| `--port 8766` | 指定监听端口，仍只监听本机 |
| `--offline` | 禁止主动请求汇率，已有缓存仍可使用 |
| `--data-dir private/work/demo` | 使用隔离数据目录；必须位于当前项目的 `private/` 内 |

不要用真实数据目录做演示或测试，也不要把 `private/` 指向链接/重定向目录。

### 本机 CLI

先启动对应端口的网站，再在另一个终端运行。下面月份仅是命令格式示例：

```powershell
python -m ledger_app.cli state --month 2025-02
python -m ledger_app.cli --port 8766 state --month 2025-02
```

CLI 的 state 会输出你所连接账本的数据，不要把输出提交到 GitHub。它不提供自然语言识别；Fork 仓库也不会复制作者的 Codex 对话或账号。

需要结构化写入时，将 payload 放在本机 `private/work/` 内，通过正式接口提交：

```powershell
python -m ledger_app.cli command --action entry.save --request-id UNIQUE-ID --file private/work/entry.json
```

先读取实际分类 ID，金额使用字符串；不要照抄别人的 ID。一个逻辑操作重试时保持同一个请求编号，只有返回 `ok:true` 才表示成功。新照片先通过 `photo.save` 得到 ID，再传入 `photo_ids`；不直接改 SQLite。

### 测试

在单独的开发副本运行：

```powershell
python -m unittest discover -s tests -v
```

测试使用虚构数据和隔离目录，部分桌面启动测试会在**该开发副本**的 `private/work/` 下创建临时账本。界面测试同样必须使用隔离数据目录，不向真实账本填写示例数据。

### 字体

钱包余额、月度收支和汇率采用本地 Inter 字体，数字使用 500 字重并启用等高、等宽数字；显示千位分隔符，不改变存储精度。

字体来源：[Inter v4.1 官方文件](https://github.com/rsms/inter/tree/v4.1/docs/font-files)。文件为 `ledger_app/static/fonts/InterVariable.woff2`，遵循随附 [SIL Open Font License 1.1](ledger_app/static/fonts/OFL.txt)。字体 SHA-256：`693b77d4f32ee9b8bfc995589b5fad5e99adf2832738661f5402f9978429a8e3`。
